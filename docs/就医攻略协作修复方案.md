# 就医攻略协作修复

## 已核实契约

- H5 调用 `/agent/visit-plan`，返回 `triage`、`hospitals`、`prep_guide`、`cost_estimate`、`weather` 和攻略字段。
- 工具层医院数据来自 `Hospital`：`id/name/rank/city`；陪诊服务价格来自 `Service.price`。医院医疗收费没有权威价格表，仍明确标记为模型参考估算。
- 独立分诊页面还依赖医院和陪诊师列表；轻量分诊仅用于攻略链路，保留独立分诊接口。

## 单个交付 Goal

协调分诊、医院、费用、准备、汇总模块与 H5 展示，完成以下修复及测试后一起交付。

1. 攻略先进行轻量症状分析，不查询医院、陪诊师和天气；独立分诊默认行为保留。
2. 医院推荐与准备清单、目标城市天气并行；费用在医院推荐完成后启动，使用候选库中真实医院的名称、等级、城市。没有有效医院时跳过医疗费用估算，不默认三甲。
3. 各非关键步骤设置超时和独立降级；返回成功的部分及 `planning_status/warnings`。分诊失败返回明确的 503，不编造科室继续生成。
4. 汇总失败使用已有结构化结果直接组装攻略，缺失步骤明确标识；不把缺失数据补成确定答案。
5. 新增费用依据、天气来源及状态展示；保持原字段兼容。日志只记录请求标识、阶段、错误类型和状态，不记录症状、凭据。

## 验收

- 真实方法配可控模型及工具替身：验证医院/天气查询次数、城市、阶段依赖和并行、权威等级覆盖、缺失医院、超时、异常、取消以及汇总降级。
- 独立分诊行为回归；异常 JSON 不能假装成功；天气模拟数据不能当成实时天气。
- 数据库查询仍在工具的 `try/finally` 内关闭；同步查询在线程运行，不阻塞事件循环。
- 前端构建通过；不调用真实 MySQL、医疗接口或模型进行自动测试，不用替身耗时宣称线上提升。
- 本次不部署、不推送、不修改简历，不新增自主规划或多轮自评机制。

## 验收结果（2026-10-08）

- `python -X utf8 -B -m unittest discover -s pz-backend/tests -v`：15 个测试通过，包括真实 FastAPI 路由的部分成功与 503 响应。
- `npm run build`（pzH5）：通过。
- `git diff --check`：通过，仅有工作区换行符转换提示。
- 正常城市查询路径：医院工具调用 3 次降至 1 次，天气 2 次降至 1 次，攻略分诊不再查询陪诊师；无本地医院时仍保留一次全国候选查询。
- 每阶段默认 25 秒超时；医院与费用顺序依赖，准备和天气并行。最长阶段预算约 100 秒，低于 H5 的 120 秒请求超时。
- 自审：保留独立分诊与原响应字段；等级、城市和平台报价由工具层数据决定；模型无效输出进入降级，父请求取消传播至异步分支；数据库工具继续在 finally 中关闭会话。
- 以上计数由代码路径及替身测试验证，不代表线上延迟或模型质量改善；真实模型、数据库及线上部署未验收。
